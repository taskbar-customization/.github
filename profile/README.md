# Windhawk - Small Mods for the Windows Shell

## One Mod, One Job

The Windows taskbar and Explorer change between releases, and the old habit was a heavy shell replacement. Windhawk's model is narrower. Each mod documents a single behavior: labels on taskbar buttons, a clock change, a middle-click action. You read that description before you enable it. A mod that says it injects into Explorer will do that. If you do not want Explorer touched, skip it.

After a Windows update, a mod can fail because the target moved. The symptom is a visual glitch or a crash in the shell, not a mystery disk error. Disable the newest mod first. Windhawk is built so that turning mods off is the recovery, which only helps if you remember which one you just enabled.

## How to Add Them

| Step | Why |
|---|---|
| Read the mod page | Know which process it changes |
| Enable one | So you can blame the right change |
| Restart the target | Explorer or the taskbar, if asked |
| Use the PC for an hour | Glitches show up in real work |
| Disable on trouble | Before you install a second mod |

## Steps

1. Install Windhawk and leave the mod list empty.  
2. Pick one mod whose description you understand.  
3. Enable it and restart Explorer if the page says to.  
4. Check the taskbar, the tray, and a file window.  
5. If anything repeats or vanishes, disable that mod before you look elsewhere.  

## Fits

People customizing their own Windows desktop. A poor fit for servers. A poor fit for a PC you cannot log into to turn a mod off. A poor fit for drivers, firmware, or antivirus. A poor fit if you want ten visual changes on day one. The safe number is one.

## Requirements

| Item | Expectation |

## Fixes

The taskbar disappeared. Disable the last mod. Restart Explorer.  
A mod shows an error after Windows Update. The target changed. Leave it off until the mod is updated.  
Two mods fight over the clock. Keep one.  
Explorer restarts in a loop. Disable mods, then add back only the one you still want.  
You wanted a new graphics driver. This does not install drivers.

## After a Feature Update

Major Windows updates are when shell mods break. Before you install one, note the mods you use. After the update, look at the taskbar before you enable anything new. If the PC is used for a presentation that day, leave the list disabled until the talk is over. A cosmetic mod is not worth a shell restart in front of other people. On a spare user account, test there first if the mod is new to you.

## Before You Enable the Next One

Use the PC for a real hour with the current mod.
Open Explorer, the tray, and a full-screen app.
If those three behave, the mod can stay.
Write its name down.
Then you may read the next mod page.
You still enable only one more, and only after that hour.
Feature updates are when you recheck, not when you add three mods.
A presentation day is a day with the list disabled.
If the taskbar glitches, the last mod comes off first.
Shell restarts are the recovery. You have to be able to sign in.
Read which process a mod injects before you enable it.
Explorer mods wait until the taskbar one has been quiet all day.
Two mods that both change the clock will flicker. Keep one.
A spare Windows account is the right place to try a mod you have never run.
The PC you present from is the wrong place.
